## 1. 首先修正会错误接受补丁的问题（B1）

- Petri 网应为全部受支持声明资源建立并初始化表示，覆盖契约独立引用、表达式、dst、call 返回等引用路径。若做裁剪，必须有覆盖上述引用且保持语义的依据。
- 不能以谓词遇到不存在的值就返回 false 的方式掩盖构网遗漏。
- `r2_query_only_Var/Atomic` 应 PASS；它们的 negated 版本应 FAIL，均与解释器一致。
- 原程序与删除最后一条写语句后的候选，初值都是 x=0，契约都是 AG(!(x==0))，所以两者都必须 FAIL。`r2_query_only_repair` 必须拒绝，不能 repaired。
- 加入 repair 端到端负例；不要靠临时禁用所有删除补丁绕过该问题。

## 2. 修正同步状态与分支（B2、B3）

- 明确 CIR 的 Condvar 锁关联策略。若支持每个等待者携带锁，解释器 wait-set 保存每个等待者自己的锁，notify/notify_all 按各自锁重取，不能复用 cv 的最后一把锁。若限定单锁，在统一支持检查中一致拒绝多锁模型并文档化。解释器不能 INVALID 而 Petri PASS。
- rendezvous 的配对选择枚举全部合法匹配，覆盖多个 receiver、多个 sender 和冻结的消息值。FIFO 消息顺序不能被用来强制等待线程 FIFO。
- 独立探针“两个 receiver 等待，一个 sender 可发送”在默认非 FIFO 线程调度语义下必须生成两个匹配分支。用手写期望断言分支内容，不能仅断言两引擎分支数量相等。
- 保留 notify_one、互斥锁、信号量、缓冲 Channel 的既有竞争语义回归；写清每一步的线性化点。

## 3. 统一契约命名与补丁范围（B4、B7）

- 去掉契约解析对 ModuleId(0) 的依赖。选定明确的稳定命名规则，如入口模块命名空间或显式 namespace；歧义短名应有明确策略，不能随声明顺序变化。
- 全限定资源／函数名精确解析，模块、资源、函数声明重排不改变同一逻辑契约的绑定和结果。
- 解析 allowed_scope.functions 中完整的 module::function；所有 candidate provider 和最终权限检查共用同一规则。不得以短名集合替代完整目标身份。
- `functions=["main::t1"]` 必须允许 main::t1 的合法重排并排除 other::t1；自动与文件 provider 都需测试。

## 4. 使所有值进入路径遵守声明域（B5）

- 统一检查直接赋值、read/load 的 dst、recv 的 dst、call 实参、call 返回、CAS 结果等所有值进入位置的类型／语义取值范围。检查必须用目标类型，而不只检查数据来源类型。
- 在现有“越界语义更新禁用”的规则下，atomic_load 不能把 2 写入 [0,1] 的 x；`r2_bounded_dst_with_place` 中 EF(!(x==0 || x==1)) 应 FAIL，探索完整。
- 禁用或拒绝必须是原子的，不能先消费消息、改变调用栈或释放资源后才发现失败。
- 区分语义域边界、宿主整数溢出和分析预算，不得互相冒充。保留独立断言，不能只让两个引擎一致。

## 5. 完成有限状态化和数值错误处理（B6、B8）

- 为线程、帧、scope、handle 定义可观察生命周期，回收已不可引用的历史对象，对存活身份做正确规范化；契约所需完成事实继续使用有限监视器。
- 不可直接丢弃仍可被 join、调用返回或性质观察的信息，也不可通过增大 max_depth/max_states 宣称完成。
- `scope(worker); goto s1` 与 `spawn worker h; join h; goto s1`，worker 立即返回、仅检查 deadlock_free 时，在小预算内应完整 PASS。另测陈旧句柄、多次 join 的既定语义、嵌套 scope、重复局部名与完成次数阈值。
- SemaphoreRelease 使用 checked arithmetic。i64::MAX + 1 必须产生明确结构化结果及正确退出码，debug 和 release 不得 panic 或静默回绕。
