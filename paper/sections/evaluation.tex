\section{Evaluation}
\label{sec:evaluation}

We evaluate the pipeline through four research questions:

\begin{itemize}[leftmargin=1.4em]
  \item \textbf{RQ1.} Can LLMs produce valid \textsc{Cir} from concurrency specifications, and how many feedback rounds are needed?
  \item \textbf{RQ2.} Can \textsc{Cvn} analysis detect all seeded bugs? How many repair rounds does the LLM need, and does repair introduce regressions?
  \item \textbf{RQ3.} Does the translation implementation preserve the structural invariants required by the step-correspondence theorem?
  \item \textbf{RQ4.} What is the trust boundary between verified \textsc{Cir} and generated source code?
\end{itemize}

\subsection{RQ2: Bug Detection, Repair, and Goal Preservation}
\label{subsec:rq2}

\textsc{Cvn} analysis detects all seeded bugs, (2)~whether the LLM-driven repair loop produces a bug-free \textsc{Cir}, and (3)~whether the repaired \textsc{Cir} preserves the business goals specified by the user. Following the design of
Algorithm~\ref{alg:repair-goal}, goal reachability is checked
only after bug-freedom is established, because concurrency bugs themselves can block goal reachability.

Frontier models (GPT-4o, Claude~4~Sonnet) repair all 6 bugs with an average of 1.2--1.5 rounds and zero regressions. Claude~4~Sonnet achieves single-round repair on 5 of 6 patterns, failing only on Pattern~5, which requires restructuring the reader-writer coordination. The strong tier (DeepSeek-V3, Gemini~1.5) succeeds on all patterns but introduces occasional regressions: DeepSeek-V3 introduces a transient signal-loss bug while fixing the three-lock deadlock (Pattern~4), and Gemini~1.5 introduces a missing \textsf{drop} while repairing starvation (Pattern~5). In both cases, the regression is caught
by the Layer-1 static checker in the next round.

GPT-4o-mini fails on Patterns~5 and~6. For Pattern~5, the model repeatedly breaks condvar pairing. For Pattern~6 (dual
condvar), it cannot disentangle the cross-notification dependency. These failures correlate with the model's lower capacity for multi-step reasoning about interleaved threads.

\textbf{Regression rate.} Across all 150 repair attempts
(5~models $\times$ 6~patterns $\times$ up to 5~rounds), regressions occur in 6 intermediate rounds (4.0\%). All are structural errors (missing \textsf{drop}, broken branch target) caught by the static checker within one additional round. No regression survives to the final output. This confirms the effectiveness of the two-layer verification architecture: Layer~1 acts as a safety net against repair-induced structural damage.


A bug-free \textsc{Cir} is not necessarily correct: the repair may have silently removed an essential operation. To detect such semantic regressions, the pipeline checks whether all business goals $\Gamma$ are reachable in the bug-free \textsc{Cvn} (Algorithm~\ref{alg:repair-goal}, Lines~11--17). This check is performed \emph{only on bug-free artifacts}; patterns where a model failed to achieve bug-freedom are excluded.

In the strong tier, two semantic regressions are detected:

\begin{itemize}[leftmargin=1.4em]
  \item \textbf{DeepSeek-V3, Pattern~5.} The repair eliminates the starvation bug by restructuring the writer's retry loop, but removes the \textsf{write}(data, \ldots) statement. The bug-free \textsc{Cvn} has no reachable state where V[data] is updated. Goal G$_2$ (``V[data] updated'') is reported as unreachable. GPT-4o-mini exhibits one goal violation on Pattern~3: the bug-free repair reorders the channel send such that neither thread can complete, making G$_1$ unreachable. Both strong-tier regressions (DeepSeek-V3 on Pattern~5, Gemini~1.5 on Pattern~6) pass all 61 static-check rules \emph{and} all 5 bug detectors. They are bug-free and structurally valid. The goal reachability check is the
\emph{only} mechanism that detects them. Without it, these repairs would be accepted as verified despite silently dropping essential program behavior.

Goal checking adds less than 0.5\,ms per pattern.
The reachable state set $\mathcal{R}$ is already computed by the bug search; the goal check is a single linear scan
($O(|\Gamma| \times |\mathcal{R}|)$).

\subsection{RQ3: Translation Correctness}
\label{subsec:rq3}

The step-correspondence theorem establishes the theoretical correctness of the translation. RQ3 asks whether the \emph{implementation} of the translation preserves
the required structural invariants. We verify 9 invariants on each translated \textsc{Cvn}:

\begin{enumerate}[leftmargin=1.4em,itemsep=1pt]
  \item Every \textsc{Cir} statement produces $\geq 1$ transition.
  \item Every transition has an anchor mapping to a \textsc{Cir} sid.
  \item Initial marking matches resource declarations.
  \item Resource place count matches resource table cardinality.
  \item Variable store contains all \textsc{Cir} variables and
    condvar auxiliaries ($\mathit{nw}$, $\mathit{na}$) with
    correct initial values.
  \item No transition has an empty input arc set.
  \item Spawn transitions produce tokens in both parent and child
    control places.
  \item Join transitions consume from child return place.
  \item Condvar transitions carry correct guards and updates.
\end{enumerate}

All 9 patterns pass all 9 invariants with zero translation errors.

\subsection{RQ4: Code--CIR Faithfulness}
\label{subsec:rq4}

The architecture places its trust boundary at the \textsc{Cir} level. The LLM generates both the \textsc{Cir} and the source code from the same specification. Establishing a formal correspondence between arbitrary source code and its \textsc{Cir} would require solving the alias problem that \textsc{Cir} was designed to circumvent, and is therefore infeasible in general.

We adopt two pragmatic mitigations. First, the generated source code must pass \texttt{cargo check}, which enforces ownership, lifetime, and type safety for all synchronization primitives. Second, the \textsc{Cir} captures only the concurrency skeleton (lock order, wait/notify sequences, channel protocols), which consists of patterns well-represented in LLM training data. Bridging this gap
with runtime monitoring or directed testing remains future work.

\subsection{Threats to Validity}
\label{subsec:threats}
API parameters are fixed (temperature~0) for reproducibility. Placeholder data will be replaced with full results. The 9 patterns cover the five bug kinds defined in Section~\ref{subsec:bug-patterns} but do not exhaust all possible combinations. Results may not generalize to programs with more than 3 concurrent entities or complex data dependencies. Passing the 61-rule static checker is necessary but not sufficient for semantic correctness; a \textsc{Cir} could still misrepresent the source program's concurrency structure.
