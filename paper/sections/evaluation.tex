\section{Evaluation}
\label{sec:evaluation}

We evaluate the pipeline through four research questions:

% RQ1: Cir 到 Cvn 的转换是否保留了并发语义？生成的 Cvn 是否能正确分类所有预设的错误？
% RQ2: 每个 LLM 层级需要多少轮生成和修复？生成的 Cir 是否忠实地捕获了指定的并发行为？
% RQ3: 翻译后的 Cvn 和每个模式的可达状态空间有多大？
% RQ4: 目标可达性检查是否检测到逃逸了静态验证和错误自由分析的语义退化？
\begin{itemize}[leftmargin=1.4em]
  \item \textbf{RQ1 (Translation correctness).}
    Does the \textsc{Cir}-to-\textsc{Cvn} translation preserve concurrency semantics, and does the resulting
    \textsc{Cvn} correctly classify all seeded bugs?
  \item \textbf{RQ2 (Loop convergence).}
    How many generation and repair rounds does each LLM tier require, and does the LLM-generated \textsc{Cir}
    faithfully capture the specified concurrency behavior?
  \item \textbf{RQ3 (State-space scale).}
    What is the size of the translated \textsc{Cvn} and the reachable state space for each pattern?
  \item \textbf{RQ4 (Goal preservation).}
    Does goal-reachability checking detect semantic regressions that escape both static validation and
    bug-freedom analysis?
\end{itemize}

We evaluate five LLMs spanning three capability tiers: GPT-5 and Claude~4.7~Opus (\emph{frontier}), Qwen3-Max and Gemini~3~Pro (\emph{strong}), and DeepSeek-V3 (\emph{compact}). The front-end is evaluated on Rust synchronization idioms, but the \textsc{Cir}/\textsc{Cvn} back-end is defined over language-level synchronization semantics rather than Rust-specific syntax.

\subsection{RQ1: Translation Correctness}
\label{subsec:rq1}
% RQ1 从两个层面评估 \textsc{Cir} 到 \textsc{Cvn} 的转换:通过转换规则的构造而成立的形式模拟特性,以及对 9 模式矩阵的经验不变性检查。
RQ1 evaluates the \textsc{Cir}-to-\textsc{Cvn} translation at two levels: formal simulation properties that hold by construction of the translation rules, and empirical invariant checks on the 9-pattern matrix.

Appendix~\ref{app:proofs} establishes four theorems on the translation:
(1)~\emph{forward simulation}: every CIR step maps to a  corresponding CVN firing sequence;
(2)~\emph{backward simulation}: under concrete valuation (no $\top$ values), every CVN firing maps back to a
    valid CIR step;
(3)~\emph{deadlock correspondence}: a CIR configuration is deadlocked iff its CVN encoding has no enabled
    transition; and
(4)~\emph{soundness}: under concrete valuation the translation is sound and complete for deadlock, signal
    loss, and channel block; under $\top$-abstraction, soundness is preserved but completeness may be lost.

The theorems assume that the implementation preserves certain structural properties.
We verify 9~invariants on every translated \textsc{Cvn}:
(1)~every CIR statement produces $\geq 1$ transition;
(2)~every transition anchors to a CIR \textsf{sid};
(3)~initial marking matches resource declarations;
(4)~resource-place count equals resource-table cardinality;
(5)~variable store contains all CIR variables and condvar
    auxiliaries with correct initial values;
(6)~no transition has an empty input-arc set;
(7)~\textsf{spawn} transitions produce tokens in both
    parent and child control places;
(8)~\textsf{join} transitions consume from the child return
    place;
(9)~condvar transitions carry correct guards and updates.

Table~\ref{tab:rq1} reports the translation size and bug-detection result for all 9~patterns. Each buggy pattern uses a fixed ground-truth CIR, making results model-independent.

All 5~definite bugs are detected with the correct bug kind. Deadlocks and signal losses are found during state-space exploration. Pattern~5 contains no definite bug: the system retains enabled transitions because a bystander thread continues executing while the two lock-contending threads block each other, so the scheduler-agnostic deadlock search correctly reports no deadlock. Instead, the goal-reachability layer flags the pattern: neither of the two contending threads can reach its declared return goal in any reachable marking, because the conflicting lock orders leave their \textsf{ret} control places unreachable. This is exactly the behaviour-regression class that motivated the introduction of goal reachability as a first-class verification property (Section~\ref{subsec:goal-reach}). The 3~baselines produce zero false positives. Combined with the 81/81 invariant checks (9~invariants $\times$ 9~patterns), this confirms that the implementation satisfies the structural preconditions assumed by the formal properties.

\subsubsection{Repair Rounds}
\label{subsubsec:rq2c}

RQ2c measures the repair loop on all 6~defective patterns. Five of them contain definite concurrency bugs (Patterns~1--4 and~6); Pattern~5 (\emph{partial deadlock}) is a behavioural regression in which the \textsc{Cvn} search reports no deadlock, yet two contending threads permanently stall and the declared business goals are unreachable. The repair loop now treats goal-unreachability as a first-class trigger on equal footing with deadlock and signal loss: when the Layer-2a search returns $\mathcal{B}=\emptyset$ but Algorithm~\ref{alg:repair-goal} reports at least one unmet goal, a synthetic \textsc{GoalUnreachable} diagnostic is fed back into the repair prompt and the loop continues. Pattern~5 therefore enters RQ2c on its own merits.

% Pattern~6 是整个矩阵中最难的一项: 5 个模型中只有 Gemini~3~Pro 能够解开两个交叉通知依赖 (cv1 ↔ cv2) 而不引入其他 bug。 一个典型的失败模式是将 condvar wait 迁移到一个没有关联的互斥锁上,触发 T102 翻译错误;另一个是在 notify 前没有重新获取互斥锁,从而引入新的信号丢失。所有这些回归都被后端 (静态检查器、CVN 翻译层、目标可达性) 捕获并反馈,但在 5 轮预算内不足以指导模型正确修复。
Pattern~6 is the hardest cell: only Gemini~3~Pro disentangles the two cross-notification dependencies without introducing fresh bugs. Common failure modes include moving a \textsf{cv.wait} off its associated mutex (triggering translator rule~T102) and introducing a new signal-loss by emitting \textsf{notify} outside the protecting critical section. These regressions are caught by the back-end and surfaced to the LLM, but five rounds are not enough for the weaker models to converge.

% 在 30 个模型--模式修复任务 (5 个模型 × 6 个模式) 中, 共发生 30 次中间回归。静态检查器捕获了其中大部分 (13次 JSON / 命名错误), CVN 翻译层捕获了 14 次语义错误 (T102: wait 指向错误的互斥锁), 目标可达性检查捕获了 1 次。在所有成功的修复中, 没有回归存活到最终接受的 CIR 中; 多层验证的一个重要属性是每一种错误类别都有对应的反馈通道.
Across the 30 model--pattern repair tasks (5~models $\times$ 6~patterns), regressions occur 30~times in intermediate rounds (static: $\sim$13, translation/T102: $\sim$14, goal-unreachability: $\sim$1, bug-kind drift: $\sim$2). No regression survives to the final accepted \textsc{Cir}. The multi-layer pipeline's defining property is that every regression class has a dedicated feedback channel.


\subsection{RQ3: State-Space Scale}
\label{subsec:rq3}

% 复用 RQ1 表中数据,做独立分析.
Table~\ref{tab:rq1} (Section~\ref{subsec:rq1}) reports the \textsc{Cvn} size ($|P|$, $|T|$) and reachable state count for each pattern. The largest pattern (Pattern~4, three-lock circular with 3 threads and 3~mutexes) produces 396~reachable states and completes analysis in under 1\,ms. All patterns remain below 400~states.

State-space size is governed by three factors: (1)~the number of concurrent threads~$k$, (2)~the lock-nesting depth~$d$, and (3)~the variable-domain cardinality~$|D|$. The current matrix uses $k \leq 3$, $d \leq 2$, $|D| \leq 3$, yielding tractable spaces. Moving to $k=4$ or richer data domains will increase the state space exponentially; partial-order reduction and symmetry breaking are planned future extensions. Across the 9~patterns the average ratio is 1.6~places and 1.3~transitions per CIR statement. Condvar-related patterns exhibit a transition-per-statement ratio close to 1.5 due to the wait/notify decomposition into 4~transitions per \textsf{wait} site (Section~\ref{subsec:condvar}). Full state-space exploration completes in $\leq 1$\,ms for all patterns on commodity hardware, including deadlock detection and the signal-loss sub-classification of deadlock counterexamples. Goal-reachability checking (RQ4) adds negligible overhead by reusing the already-computed reachable set.


\subsection{RQ4: Goal Preservation}
\label{subsec:rq4}
% 通过明确缺陷检查的 Cir 并不一定是正确的。缺陷检测器无法检测到两种不同的故障模式:(1)修复引起的回归和(2)活锁阻塞。 目标可达性检查(算法~\ref{alg:repair-goal},第 11-17 行)旨在检测第一种故障模式。我们还将检验它是否能够发现第二种故障模式。
A \textsc{Cir} that passes the definite-bug check is not necessarily correct. Two distinct failure modes remain invisible to the deadlock / signal-loss detectors: (1)~repair-induced behaviour regressions that silently drop functionality and (2)~partial deadlocks that leave the system globally live but permanently block the threads responsible for reaching the declared goals.
Goal-reachability checking (Algorithm~\ref{alg:repair-goal}) is designed to cover both failure modes as a single first-class property; when a repaired \textsc{Cir} is bug-free but still has unmet goals the pipeline raises a synthetic \textsc{GoalUnreachable} diagnostic and routes it back into the same repair loop used for deadlocks and signal losses (Section~\ref{subsubsec:rq2c}).

% 我们评估两个独立的维度。第一个(表~\ref{tab:rq4-goal-detection})测量目标可达性检查本身在 8 个模式上的行为，不管是否来自 LLM：对每个测试用例的 ground-truth CIR 运行算法~\ref{alg:repair-goal}，看是否能把可达目标识别为可达、把不可达目标识别为不可达。这是对检查器本身的合理性/充分性的验证。第二个(表~\ref{tab:rq4-loop-effect})则测量同一个检查在 LLM 修复循环中作为反馈通道的效用:有多少个模型-模式对只在目标反馈下才被接受？
We evaluate two orthogonal dimensions. This is a soundness/completeness check on the algorithm. Second, Table~\ref{tab:rq4-loop-effect} measures the check's utility \emph{as a feedback channel inside the repair loop}: how many model--pattern pairs are accepted only because the goal-reachability verdict was fed back to the LLM?

\subsection{Threats}
\label{subsec:trust-boundary}

% 该架构将信任边界设置在 Cir 层。LLM 根据同一规范生成 Cir 和源代码。在任意源代码与其对应的 Cir 之间建立正式对应关系需要解决 Cir 旨在规避的别名问题,因此通常是不可行的。
The architecture places its trust boundary at the \textsc{Cir} level. The LLM generates both the \textsc{Cir} and the source code from the same specification. Establishing a formal correspondence between arbitrary source
code and its \textsc{Cir} would require solving the alias problem that \textsc{Cir} was designed to circumvent, and is therefore infeasible in general.

% 我们采用了两种务实的缓解措施。首先,生成的源代码必须通过 Cargo 检查,该检查强制执行所有同步原语的所有权、生命周期和类型安全。其次,Cir 仅捕获并发框架,该框架由 LLM 训练数据中充分体现的模式组成。虽然当前的原型是在 Rust 上进行评估的,但信任边界问题并非 Rust 特有;任何将源代码映射到 Cir 的前端都会出现此问题。通过运行时监控或定向测试来弥合这一差距仍是未来的工作方向。
We adopt two pragmatic mitigations. First, the generated source code must pass \texttt{cargo check}, which enforces ownership, lifetime, and type safety for all synchronization primitives. Second, the \textsc{Cir} captures only the concurrency skeleton, which consists of patterns well represented in LLM training data. Although the present prototype is evaluated on Rust, the trust-boundary issue is not specific to Rust; it arises for any front-end that maps source code into \textsc{Cir}. Reconstructing CIR or Petri nets from source code using static analysis can bridge this gap and remains a direction for future work.
