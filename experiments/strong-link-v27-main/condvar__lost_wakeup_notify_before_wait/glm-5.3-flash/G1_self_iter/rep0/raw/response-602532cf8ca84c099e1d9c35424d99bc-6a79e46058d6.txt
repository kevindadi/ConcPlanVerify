```rust
use std::sync::{Arc, Condvar, Mutex};
use std::thread;

fn main() {
    // R2: one lock (m), one condition variable (cv), one boolean flag (ready)
    // guarded by the lock, shared between the two roles.
    let shared = Arc::new((Mutex::new(false), Condvar::new()));

    let waiter_shared = Arc::clone(&shared);
    let notifier_shared = Arc::clone(&shared);

    // R1: waiter and notifier run concurrently as spawned threads.
    let waiter = thread::spawn(move || {
        let (m, cv) = &*waiter_shared;
        // R4/R7: check the flag while holding the lock.
        let mut ready = m.lock().unwrap();
        // R4: wait only while the flag is false; re-check after every wake
        // (the while loop handles spurious wakeups and lost-signal races).
        while !*ready {
            // R7: the lock is released while blocked and reacquired on wake.
            ready = cv.wait(ready).unwrap();
        }
    });

    let notifier = thread::spawn(move || {
        let (m, cv) = &*notifier_shared;
        // R3/R6/R7: set the flag to true while holding the lock, then signal.
        let mut ready = m.lock().unwrap();
        *ready = true;
        cv.notify_one();
        // R3: lock is released when `ready` is dropped at scope end.
    });

    // R8: join both roles so every interleaving terminates with both finished.
    waiter.join().unwrap();
    notifier.join().unwrap();

    // R7: read the flag only while the lock is held.
    let (m, _) = &*shared;
    let ready = m.lock().unwrap();

    // R10: print exactly one line and exit.
    println!("DONE ready={}", *ready);
}
```

**Concurrency defects repaired and justification:**

1. **Lost wakeup / missed signal (R5, R6):** The notifier sets `ready = true` *before* calling `notify_one()`, and both operations happen while holding the `m` lock. If the notifier runs entirely before the waiter even starts waiting, the waiter's initial check under the lock sees `ready == true` and never blocks — the signal cannot be missed.

2. **Predicate re-check after wake (R4):** The waiter uses `while !*ready { cv.wait(...) }` instead of `if`. This protects against spurious wakeups and guarantees the waiter only exits the loop when the predicate is genuinely true under the lock.

3. **Lock released while blocked (R7):** `Condvar::wait` atomically releases the mutex while sleeping and reacquires it before returning, so the notifier is never permanently blocked on `m` while the waiter waits.

4. **Flag access only under the lock (R2, R7):** Every read and write of `ready` occurs while the corresponding `MutexGuard` is alive; the guard is dropped (releasing the lock) at scope end, including after the notifier's signal.

5. **Guaranteed termination (R8, R9):** Both threads are joined before the final read. Since the notifier unconditionally sets `ready = true` under the lock and the waiter only exits once it observes `true`, every schedule ends with both roles finished and the flag true.

6. **Exact output (R10):** The program prints exactly `DONE ready=true` (the flag is guaranteed true at that point) and exits.
