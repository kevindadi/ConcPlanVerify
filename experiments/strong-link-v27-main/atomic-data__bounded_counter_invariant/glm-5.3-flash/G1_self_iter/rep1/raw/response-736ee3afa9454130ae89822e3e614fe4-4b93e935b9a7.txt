## Review notes (defects found and repaired)

1. **Data race on `c`** — the counter was shared by raw reference across threads. Repaired by wrapping `c` in `Arc<Mutex<…>>` so both workers own a handle to the same lock-protected variable (R2, R4).
2. **Read outside the critical section** — a worker read `c` before acquiring `m`, allowing a lost update. Repaired: the lock is acquired *first*, and both the read and the write happen while the `MutexGuard` is held (R3, R4).
3. **Range violation** — nothing checked the declared range. Repaired: the worker asserts the value is in `0..=2` before incrementing, so `c` can only ever be 0, 1, or 2 (R5).
4. **Supervisor not waiting** — the supervisor could exit before workers finished. Repaired: `main` joins both worker handles before printing (R1, R6).
5. **Deadlock risk** — no nested locks and the guard is released at scope end before `join`, so every schedule terminates (R6).
6. **Output** — after both workers complete, `c == 2`; the completion flag `done` is derived as `(c == 2) as u32`, which is `1` on every terminating schedule, so exactly `DONE done=1` is printed (R7).

## Program

```rust
use std::sync::{Arc, Mutex};
use std::thread;

// Shared resource: c ranges over 0..=2, starts at 0.
// m is the mutual-exclusion lock protecting c.
type Shared = Arc<Mutex<u32>>;

// Worker role w1: add 1 to c while holding m.
fn w1(c: Shared) {
    let m = c.lock().unwrap();      // acquire m
    let v = *m;                     // read c under m
    debug_assert!(v <= 1, "c out of range: {}", v); // R5: stays in 0..=2
    *m = v + 1;                     // write c under m
    drop(m);                        // release m
}

// Worker role w2: add 1 to c while holding m.
fn w2(c: Shared) {
    let m = c.lock().unwrap();      // acquire m
    let v = *m;                     // read c under m
    debug_assert!(v <= 1, "c out of range: {}", v); // R5: stays in 0..=2
    *m = v + 1;                     // write c under m
    drop(m);                        // release m
}

fn main() {
    // R2: single shared counter, range 0..=2, starts at 0.
    let c: Shared = Arc::new(Mutex::new(0));

    // R1: supervising task launches the two workers.
    let h1 = {
        let c = Arc::clone(&c);
        thread::spawn(move || w1(c))
    };
    let h2 = {
        let c = Arc::clone(&c);
        thread::spawn(move || w2(c))
    };

    // R1/R6: wait for both workers; every interleaving terminates
    // because neither worker blocks except on m, which is always
    // released promptly.
    h1.join().expect("w1 panicked");
    h2.join().expect("w2 panicked");

    // Read final value under the lock (R4).
    let m = c.lock().unwrap();
    let final_c = *m;
    drop(m);

    // R7: done is the completion flag; both workers finished and the
    // counter reached its final value, so done == 1 on every schedule.
    let done = (final_c == 2) as u32;
    println!("DONE done={}", done);
}
```

**Why the invariants hold:** each worker's read-modify-write of `c` occurs entirely inside the critical section guarded by `m`, so the two increments are serialized; `c` takes only the values 0 → 1 → 2, never leaving `0..=2` in any reachable state. Since the only lock is non-nested and always released, all interleavings terminate, and the supervisor prints exactly one line, `DONE done=1`, before exiting.
