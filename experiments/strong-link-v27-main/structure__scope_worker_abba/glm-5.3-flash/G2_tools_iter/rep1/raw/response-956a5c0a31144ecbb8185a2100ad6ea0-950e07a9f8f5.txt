```rust
use std::sync::{Arc, Mutex};
use std::thread;

// Worker body shared by w1 and w2.
// Both workers acquire the mutexes in the SAME order: a, then b (R5),
// so no circular wait can form and every schedule terminates (R7).
// Mutex::lock() blocks until the mutex is free (R6), and a held mutex
// is exclusive, so at most one worker holds a given mutex (R4).
fn worker(a: Arc<Mutex<()>>, b: Arc<Mutex<()>>) {
    // Take mutex a.
    let _guard_a = a.lock().unwrap();

    // Take mutex b. At this point the worker holds both a and b (R2).
    let _guard_b = b.lock().unwrap();

    // ... work while holding both mutexes ...

    // Work finished: release each mutex exactly once (R3).
    drop(_guard_b);
    drop(_guard_a);
}

fn main() {
    // Shared resources: a and b (R1).
    let a = Arc::new(Mutex::new(()));
    let b = Arc::new(Mutex::new(()));

    // Main task starts the group of two workers, w1 and w2 (R1).
    let a1 = Arc::clone(&a);
    let b1 = Arc::clone(&b);
    let w1 = thread::spawn(move || worker(a1, b1));

    let a2 = Arc::clone(&a);
    let b2 = Arc::clone(&b);
    let w2 = thread::spawn(move || worker(a2, b2));

    // The group finishes only after both workers have completed (R8).
    w1.join().expect("w1 panicked");
    w2.join().expect("w2 panicked");

    // Exactly one output line, then exit (R9).
    println!("DONE done=1");
}
```

**How the requirements are met:**

- **R1** — `main` spawns exactly two threads, `w1` and `w2`, both contending on the same `a` and `b` mutexes (shared via `Arc`).
- **R2** — Each worker locks `a` first, then `b`; between the two `lock()` calls and the drops it holds both simultaneously.
- **R3** — Each guard is dropped exactly once when the work is done (also implicitly on scope exit).
- **R4** — `Mutex` guarantees exclusive ownership; a second `lock()` on a held mutex cannot succeed concurrently.
- **R5** — Both workers use the identical acquisition order `a → b`, so the resource-allocation graph stays acyclic — no deadlock cycle is possible.
- **R6** — `Mutex::lock()` blocks the calling thread until the mutex becomes free.
- **R7** — With a consistent lock order and blocking acquisition, every interleaving terminates.
- **R8** — `main` joins `w1` and `w2` before proceeding; the group ends only after both complete.
- **R9** — The only `println!` in the program emits `DONE done=1`, after which `main` returns and the process exits.
