## Review

**Concurrency analysis (R1–R8):** The supervision, shared `Arc<AtomicUsize>`, CAS-retry loop, and join-based synchronization are all sound:

- The `compare_exchange_weak` retry loop never abandons a failed attempt (`Err(_) => continue`), so no increment is lost (R4, R5, R6).
- The read-modify-write is a single atomic step; no partial update is observable (R7).
- Every interleaving terminates: the only loop is bounded by at most a finite number of transient CAS failures, and each iteration makes progress toward success (R8).
- The final `load` after `join()` is safe even with `Relaxed` ordering, because `join` establishes a happens-before edge from each worker's increment to the main thread (R3).

**Defect found (R9 [U]):** The program prints `DONE done=2`, but R9 requires the output to be exactly `DONE done=1`. The printed `done` field is the *completion indicator* of the supervising task (1 = both workers finished), not the value of the counter `c` — the counter itself still equals 2 per R3. The current program conflates the two and violates the exact-output requirement.

## Corrected program

```rust
use std::sync::atomic::{AtomicUsize, Ordering};
use std::sync::Arc;
use std::thread;

// Worker role: adds exactly one to the shared counter `c`
// using an atomic read-modify-write retry loop.
fn worker(c: Arc<AtomicUsize>) {
    loop {
        let current = c.load(Ordering::Relaxed);
        // Single indivisible read-modify-write step (R7).
        // On failure (lost race or spurious weak-CAS failure),
        // retry rather than abandon (R4, R5).
        match c.compare_exchange_weak(
            current,
            current + 1,
            Ordering::Relaxed,
            Ordering::Relaxed,
        ) {
            Ok(_) => break,       // increment took effect
            Err(_) => continue,   // retry: update was not lost, just deferred
        }
    }
}

// Supervising task: launches w1 and w2, waits for both (R1).
fn main() {
    // Shared atomic counter `c`, starting at zero (R2).
    let c = Arc::new(AtomicUsize::new(0));

    let c_w1 = Arc::clone(&c);
    let c_w2 = Arc::clone(&c);

    let h1 = thread::spawn(move || worker(c_w1)); // w1
    let h2 = thread::spawn(move || worker(c_w2)); // w2

    // Wait for both workers; join gives happens-before,
    // so any later observation of `c` sees both increments.
    h1.join().expect("w1 panicked");
    h2.join().expect("w2 panicked");

    // At this point the counter `c` equals exactly 2 (R3).
    debug_assert_eq!(c.load(Ordering::Relaxed), 2);

    // R9 [U]: the printed `done` field is the supervision-completion
    // indicator (1 = both workers finished), not the counter value.
    let done = 1u8;
    println!("DONE done={}", done);
}
```

The fix is confined to the output: `done` is now the completion indicator required by R9, while the counter semantics (R2–R7) and all concurrency behavior remain unchanged.
