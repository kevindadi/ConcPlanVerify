## Analysis of defects and repairs

**Defect (violates R5, R8):** If the two workers acquire the locks in *different* orders (e.g. `t1` takes `a` then `b`, while `t2` takes `b` then `a`), an interleaving exists where each worker holds one lock and blocks forever on the other — a classic deadlock. This breaks R5 and makes some schedules non-terminating (R8).

**Repair:** Impose a **global lock hierarchy** — both workers acquire the locks in the identical fixed order (`a` first, then `b`). With a consistent acquisition order, the "hold-and-wait" cycles required for deadlock cannot form, so every interleaving terminates (R8) and no worker can be left waiting forever (R5).

**Other requirements check:**
- R1: one main thread + two spawned workers named `t1`, `t2`. ✔
- R2: `Mutex` guarantees exclusive ownership of each lock. ✔
- R3: both guards are alive simultaneously during the critical work. ✔
- R4: `Mutex::lock()` blocks until the lock is free, then continues. ✔
- R6: main `join()`s both workers before printing. ✔
- R7: RAII guards (`MutexGuard`) release both locks automatically when dropped at scope end, before the thread finishes — even if the critical work panicked. ✔
- R9: exactly one `println!` producing `DONE t1=1 t2=1`. ✔

## Program

```rust
use std::sync::{Arc, Mutex};
use std::thread;

fn main() {
    // Shared resources: lock `a` and lock `b`.
    let a = Arc::new(Mutex::new(()));
    let b = Arc::new(Mutex::new(()));

    // Worker t1: acquires locks in the global order a -> b.
    let a1 = Arc::clone(&a);
    let b1 = Arc::clone(&b);
    let t1 = thread::spawn(move || {
        let _guard_a = a1.lock().unwrap(); // blocks until `a` is free (R4)
        let _guard_b = b1.lock().unwrap(); // blocks until `b` is free (R4)

        // Critical work: both locks held simultaneously (R3).
        // Guards drop here at scope end, releasing a then b (R7).
    });

    // Worker t2: acquires locks in the SAME global order a -> b.
    // Consistent ordering makes deadlock impossible (R5, R8).
    let a2 = Arc::clone(&a);
    let b2 = Arc::clone(&b);
    let t2 = thread::spawn(move || {
        let _guard_a = a2.lock().unwrap();
        let _guard_b = b2.lock().unwrap();

        // Critical work: both locks held simultaneously (R3).
        // Guards drop here at scope end, releasing a then b (R7).
    });

    // Main thread starts both workers and waits for both to finish (R1, R6).
    t1.join().unwrap();
    t2.join().unwrap();

    // Exactly one output line, then exit (R9).
    println!("DONE t1=1 t2=1");
}
```

**Why every schedule terminates (R8):** Since both threads request `a` before `b`, at most one worker can hold `a`; the other blocks on `a` while holding nothing. The holder of `a` can always eventually obtain `b` (its only competitor for `b` is blocked on `a`), finish its critical work, and release both — unblocking the other worker. No circular wait is possible, so all interleavings complete.
