```rust
use std::sync::mpsc::sync_channel;
use std::thread;

fn main() {
    // R2: sync_channel(0) is a rendezvous channel — zero buffering.
    // A send on `ch` blocks until a receiver takes, so the two tasks
    // must meet to exchange the value.
    let (ch_tx, ch_rx) = sync_channel::<i32>(0);

    // R1: spawn both tasks before joining either, so they run concurrently.
    let s1 = thread::spawn(move || {
        // R3: sender passes exactly one value.
        // R4: this blocks only until `r` takes; `r` is already running,
        // so the wait is bounded by the rendezvous itself.
        ch_tx.send(1).expect("s1: receiver disappeared");
    });

    let r = thread::spawn(move || {
        // R3: receiver takes exactly one value and returns it.
        // R4: blocks only until `s1` sends; `s1` is already running.
        ch_rx.recv().expect("r: sender disappeared")
    });

    // R5: join both tasks so every interleaving terminates with both
    // tasks finished before the program proceeds to print.
    let s1_result = s1.join().expect("s1 panicked");
    let value = r.join().expect("r panicked");

    // R6: after the rendezvous, the channel holds nothing; dropping
    // `ch_tx`/`ch_rx` at scope end leaves it empty.
    let _ = s1_result;

    // R7: print exactly `DONE done=1`.
    let done = if value == 1 { 1 } else { 0 };
    println!("DONE done={}", done);
}
```

**Concurrency defects repaired and justified:**

1. **Unbuffered channel (R2):** Used `sync_channel::<i32>(0)` instead of `mpsc::channel()`. A regular MPSC channel buffers, so the sender could finish without ever meeting the receiver. `sync_channel(0)` forces a rendezvous: `send` returns only when `recv` takes the value.

2. **No premature main exit (R4/R5):** Both handles are joined before printing. Without `join`, `main` could return while the tasks are still blocked, killing a waiting partner — a potential hang or lost value. Joining guarantees both tasks complete on every interleaving.

3. **No deadlock (R4):** Both tasks are spawned *before* either is joined. If `s1` were joined before `r` was spawned, `s1` would block forever on the rendezvous with no partner. Spawning both first ensures each blocking side has its partner already running.

4. **Exactly one value, empty channel (R3/R6):** The sender sends once, the receiver receives once; after the rendezvous the channel is empty, and both endpoints drop at scope end.

5. **Deterministic output (R7):** `done` is derived from the received value, and the program prints exactly one line, `DONE done=1`, then exits.
