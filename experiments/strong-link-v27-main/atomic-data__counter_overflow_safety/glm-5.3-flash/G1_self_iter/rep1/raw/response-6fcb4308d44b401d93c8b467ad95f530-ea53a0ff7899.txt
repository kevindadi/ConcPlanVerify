## Review notes (defects checked and justified)

- **Data race on `c`** — eliminated: every read and write of `c` happens while holding `m` (R4). The final read for printing is also done under `m`.
- **Lost update / double increment** — eliminated: the check `c < 1` and the write `c += 1` are a single critical section under `m`, so the two workers can never both observe `c == 0` and both increment (R3, R5).
- **Range violation** — `c` is declared with range `0..=2` and starts at `0` (R2); the guard ensures it never exceeds `1` in any interleaving (R5).
- **Deadlock / non-termination** — there are no nested locks, no loops, and no condition waits; each worker takes the lock once, acts or skips, releases, and returns. Every schedule terminates (R6).
- **Poisoned-lock panic** — impossible here: no worker can panic while holding `m`, so `m` is never poisoned.
- **Output** — exactly one worker increments (the first to acquire `m`), the other sees `c == 1` and skips, so the program prints exactly `DONE done=1` (R7).

## Program

```rust
use std::sync::{Arc, Mutex};
use std::thread;

/// Shared counter `c`.
/// Declared range: 0..=2 (fits in u8). Initial value: 0. (R2)
struct C(u8);

/// Worker body shared by w1 and w2.
/// All reads and writes of `c` occur while holding the lock `m`. (R4)
fn worker(_name: &'static str, m: &Arc<Mutex<C>>) {
    let mut g = m.lock().unwrap();
    // R3/R5: increment only if the result stays within the limit.
    // The check and the write are one critical section, so no
    // interleaving can push `c` above 1.
    if g.0 < 1 {
        g.0 += 1;
    }
    // If `c` is already 1, adding one would exceed the limit,
    // so this worker leaves `c` unchanged and finishes. (R6)
    // Lock is released here when `g` is dropped.
}

fn main() {
    // m: the mutual-exclusion lock guarding c.
    let m: Arc<Mutex<C>> = Arc::new(Mutex::new(C(0)));

    // R1: supervising task launches w1 and w2 and waits for both.
    let h1 = {
        let m = Arc::clone(&m);
        thread::Builder::new()
            .name("w1".to_string())
            .spawn(move || worker("w1", &m))
            .unwrap()
    };
    let h2 = {
        let m = Arc::clone(&m);
        thread::Builder::new()
            .name("w2".to_string())
            .spawn(move || worker("w2", &m))
            .unwrap()
    };

    h1.join().unwrap();
    h2.join().unwrap();

    // Read the final value under the lock (R4).
    let done = m.lock().unwrap().0;

    // R7: exactly one worker increments, so this prints `DONE done=1`.
    println!("DONE done={}", done);
}
```

**Why `done` is always 1:** the two workers race only for who acquires `m` first. The winner sees `c == 0`, increments to 1, and releases. The loser then sees `c == 1`, skips the increment, and finishes. No other value is reachable, so the printed line is exactly `DONE done=1` on every schedule.
