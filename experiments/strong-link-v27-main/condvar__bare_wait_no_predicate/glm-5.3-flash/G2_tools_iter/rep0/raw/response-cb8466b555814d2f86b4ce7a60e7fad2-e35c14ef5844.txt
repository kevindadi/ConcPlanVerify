```rust
use std::sync::{Arc, Condvar, Mutex};
use std::thread;

fn main() {
    // R2: one lock (m) and one condition variable (cv), guarding the boolean flag (ready).
    let shared = Arc::new((Mutex::new(false), Condvar::new()));

    // waiter role
    let waiter = {
        let m = Arc::clone(&shared.0);
        let cv = Arc::clone(&shared.1);
        thread::spawn(move || {
            // R4: check the flag first while holding the lock.
            let mut guard = m.lock().unwrap();
            // R4/R6: wait only while the flag is false; re-check after each wake.
            // R5: if the notifier already set the flag, we never enter wait.
            // R6: cv.wait releases the lock while blocked, reacquires on wake.
            while !*guard {
                guard = cv.wait(guard).unwrap();
            }
            // R9: we only get here once ready is true.
            // R10: print exactly the required line.
            println!("DONE ready=true");
        })
    };

    // notifier role
    let notifier = {
        let m = Arc::clone(&shared.0);
        let cv = Arc::clone(&shared.1);
        thread::spawn(move || {
            // R3: set the flag while holding the lock...
            let mut guard = m.lock().unwrap();
            *guard = true;
            // ...signal the condition variable while still holding the lock...
            cv.notify_all();
            // ...then release the lock.
            drop(guard);
        })
    };

    // R1: both roles run concurrently; R7: joining both guarantees termination
    // on every interleaving (the predicate loop makes early signals safe).
    waiter.join().unwrap();
    notifier.join().unwrap();
}
```

Key points addressed:

- **R5 (missed signal):** The waiter checks `ready` under the lock *before* waiting. If the notifier ran first, `ready` is already `true`, so the waiter never calls `wait` and proceeds immediately.
- **R4 (spurious wakeups):** The `while !*guard` loop re-checks the predicate after every wake, so spurious or early notifications cannot cause the waiter to pass prematurely.
- **R6 (lock while blocked):** `Condvar::wait` atomically releases `m` while blocked and reacquires it before returning, so the lock is never held while the waiter is asleep.
- **R3:** The notifier sets `ready = true` and calls `notify_all()` while holding the lock, then explicitly drops the guard.
- **R7/R8/R10:** Every schedule terminates: the flag is always set to `true` by the notifier, the waiter only exits its loop when the flag is `true`, and the sole output is `DONE ready=true`.
