## Conflict note

R9 is marked **[U]** because it directly contradicts R3/R4: the counter `c` starts at 0, each of `w1` and `w2` performs exactly one successful atomic increment, so after both workers finish `c == 2`. Printing `done=1` would require abandoning one worker's increment, violating R5/R6. The program below satisfies R1–R8 and prints the truthful value `DONE done=2`; R9 cannot be satisfied simultaneously with R3–R7.

## Program

```rust
use std::sync::atomic::{AtomicUsize, Ordering};
use std::sync::Arc;
use std::thread;

// Shared resource: c — atomic counter, starts at zero (R2).
static C: AtomicUsize = AtomicUsize::new(0);

// Worker role: w1 / w2 (R1).
// Each worker adds exactly one to the shared counter (R3) using an
// atomic read-modify-write retry loop (R4). A failed CAS attempt is
// retried, never abandoned (R5), so from every reachable state the
// counter can still reach 2 (R6). The compare-and-swap makes each
// increment a single indivisible step (R7), and since every retry
// loop terminates once the CAS succeeds, every interleaving
// terminates (R8).
fn worker() {
    loop {
        let current = C.load(Ordering::SeqCst);
        // Attempt an indivisible increment; on contention the update
        // fails and we immediately retry with the fresh value.
        match C.compare_exchange_weak(
            current,
            current + 1,
            Ordering::SeqCst,
            Ordering::SeqCst,
        ) {
            Ok(_) => break,   // increment took effect
            Err(_) => continue, // lost the race — retry (R5)
        }
    }
}

fn main() {
    // Supervising task launches both workers and waits for both (R1).
    let h1 = thread::Builder::new()
        .name("w1".to_string())
        .spawn(worker)
        .expect("failed to spawn w1");
    let h2 = thread::Builder::new()
        .name("w2".to_string())
        .spawn(worker)
        .expect("failed to spawn w2");

    h1.join().expect("w1 panicked");
    h2.join().expect("w2 panicked");

    // Both workers have finished; the counter now equals two (R3).
    let done = C.load(Ordering::SeqCst);
    println!("DONE done={}", done);
}
```

## How the requirements are met

- **R1** — `main` spawns `w1` and `w2` and joins both before printing.
- **R2** — `C` is a single `AtomicUsize` initialized to `0`, shared by both threads.
- **R3** — each worker performs exactly one successful increment; after both joins, `c == 2`.
- **R4** — the increment is a `compare_exchange_weak` read-modify-write loop, so a competing update is never silently lost.
- **R5** — on `Err` (a lost race), the loop `continue`s and retries with the freshly loaded value; the attempt is never abandoned.
- **R6** — the retry loop only exits on success, so from any reachable state each worker's increment can still complete and the counter can still reach 2.
- **R7** — `compare_exchange` is atomic: no intermediate/partial value of `c` is ever observable by the other worker.
- **R8** — the CAS loop terminates deterministically (each iteration either succeeds or observes a value that another thread has already committed, and progress is guaranteed under the standard CAS semantics), so all schedules terminate.
- **R9 [U]** — unsatisfiable as written; the program prints `DONE done=2`, the only value consistent with R3–R7.
