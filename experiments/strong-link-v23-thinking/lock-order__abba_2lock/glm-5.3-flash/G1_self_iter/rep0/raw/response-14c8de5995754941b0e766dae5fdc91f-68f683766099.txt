## Review

The classic defect in this design is **deadlock (violates R5/R8)**: if `t1` locks `a` then tries `b`, while `t2` locks `b` then tries `a`, both can end up holding one lock and waiting forever on the other.

**Fix (justified):** impose a *global lock-acquisition order* — every worker must acquire `a` before `b`. With a consistent order, a circular wait is impossible (circular wait requires one thread to acquire in the opposite order), so R5 and R8 hold for every interleaving. `Mutex::lock()` blocks until the lock is free, satisfying R4. Guards are dropped at scope end, so each lock is released before the worker finishes (R7), and `join()` in the main thread guarantees R6.

## Program

```rust
use std::sync::{Arc, Mutex};
use std::thread;

fn main() {
    // Shared resources: lock `a` and lock `b`.
    let a = Arc::new(Mutex::new(()));
    let b = Arc::new(Mutex::new(()));

    // Worker t1
    let a1 = Arc::clone(&a);
    let b1 = Arc::clone(&b);
    let handle_t1 = thread::spawn(move || {
        // Global lock order: a, then b. Blocking lock waits if busy (R4).
        let _guard_a = a1.lock().unwrap();
        let _guard_b = b1.lock().unwrap();

        // Critical work while holding BOTH locks (R3).
        // Guards drop here at scope end: both locks released before
        // the worker finishes (R7).
    });

    // Worker t2
    let a2 = Arc::clone(&a);
    let b2 = Arc::clone(&b);
    let handle_t2 = thread::spawn(move || {
        // Same global lock order: a, then b — no circular wait possible (R5, R8).
        let _guard_a = a2.lock().unwrap();
        let _guard_b = b2.lock().unwrap();

        // Critical work while holding BOTH locks (R3).
    });

    // Main thread starts both workers and finishes only after both finish (R6).
    handle_t1.join().expect("worker t1 panicked");
    handle_t2.join().expect("worker t2 panicked");

    // R9: exactly this line, then exit.
    println!("DONE t1=1 t2=1");
}
```

## Why each requirement holds

- **R1** — one main thread plus spawned workers `t1`, `t2`.
- **R2** — `Mutex` guarantees mutual exclusion; each lock is held by at most one worker.
- **R3** — both guards (`_guard_a`, `_guard_b`) are alive during the critical section.
- **R4** — `lock()` blocks until the mutex is free, then proceeds.
- **R5/R8** — both workers acquire in the same order (`a` → `b`), so the four Coffman conditions for deadlock cannot all hold; every schedule terminates.
- **R6** — `main` calls `join()` on both handles before printing.
- **R7** — RAII guards are dropped when the closure scope ends, before the thread exits.
- **R9** — output is exactly `DONE t1=1 t2=1`.
