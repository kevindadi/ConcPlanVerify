# Revised Program

Based on the tool feedback, the deadlock came from the inner tasks acquiring the locks in **opposite orders** (one took `a` then `b`, the other took `b` then `a`), which allowed a wait cycle to form. The fix (R4) is to have both inner tasks acquire `a` before `b`, in the same order, so no cycle can ever form. The outer worker now also explicitly awaits both inner tasks before completing (R5), and the program prints exactly `DONE done=1` (R7).

**Cargo.toml**

```toml
[package]
name = "lock_order_demo"
version = "0.1.0"
edition = "2021"

[dependencies]
tokio = { version = "1", features = ["full"] }
```

**src/main.rs**

```rust
use std::sync::Arc;
use tokio::sync::Mutex;

// Shared resources: a (lock), b (lock).
// Both inner tasks acquire them in the SAME order: a, then b.
// Because the order is consistent, no wait cycle can form (R4),
// so every interleaving terminates (R6).

async fn inner_task(
    name: &'static str,
    a: Arc<Mutex<()>>,
    b: Arc<Mutex<()>>,
) {
    // Acquire a first...
    let _guard_a = a.lock().await;
    // ...then b. Both inner tasks follow this same order.
    let _guard_b = b.lock().await;

    // At this point the task holds both a and b simultaneously (R3).
    println!("{} holds a and b", name);

    // Guards drop here, releasing b then a, in reverse acquisition order.
    drop(_guard_b);
    drop(_guard_a);
}

// Role: outer. Starts the nested group of two inner tasks (R2)
// and completes only after both inner tasks have finished (R5).
async fn outer(a: Arc<Mutex<()>>, b: Arc<Mutex<()>>) {
    let h1 = tokio::spawn(inner_task("x1", a.clone(), b.clone()));
    let h2 = tokio::spawn(inner_task("x2", a.clone(), b.clone()));

    // Wait for both inner tasks; outer completes only after they finish.
    h1.await.expect("x1 panicked");
    h2.await.expect("x2 panicked");
}

// Role: main task. Starts one outer worker (R1).
#[tokio::main]
async fn main() {
    let a = Arc::new(Mutex::new(())); // resource: a
    let b = Arc::new(Mutex::new(())); // resource: b

    let outer_handle = tokio::spawn(outer(a, b));

    // Main task waits for the outer worker to complete.
    outer_handle.await.expect("outer panicked");

    // Exactly one line of output at the end (R7).
    println!("DONE done=1");
}
```

## Why this satisfies the requirements

- **R1** — `main` spawns exactly one `outer` worker and awaits it.
- **R2** — `outer` spawns the nested group of two inner tasks, `x1` and `x2`.
- **R3** — Each inner task holds `_guard_a` and `_guard_b` at the same time.
- **R4** — Both inner tasks lock `a` before `b`. With a consistent global lock order, a cycle in the wait-for graph is impossible, so the original deadlock (tasks grabbing the locks in opposite orders) cannot recur.
- **R5** — `outer` awaits both `JoinHandle`s before returning, so it completes strictly after both inner tasks finish.
- **R6** — Lock acquisition is non-cyclic and every `await`/`join` chain terminates, so all schedules terminate.
- **R7** — The only `println!` at the top level prints `DONE done=1` once, then the program exits.
