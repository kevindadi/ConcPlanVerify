```rust
use std::sync::{Arc, Mutex};
use std::thread;

fn main() {
    // Shared resources: a (lock), b (lock)
    let a = Arc::new(Mutex::new(()));
    let b = Arc::new(Mutex::new(()));

    // Worker w1: takes a, then b — same order as w2 (R5)
    let a1 = Arc::clone(&a);
    let b1 = Arc::clone(&b);
    let w1 = thread::spawn(move || {
        let _ga = a1.lock().unwrap(); // waits if held (R6)
        let _gb = b1.lock().unwrap(); // waits if held (R6)
        // Critical section: w1 now holds BOTH a and b simultaneously (R2)
        // ... work ...
        // Guards drop here at end of scope: each mutex released exactly once (R3)
    });

    // Worker w2: takes a, then b — identical order (R5)
    let a2 = Arc::clone(&a);
    let b2 = Arc::clone(&b);
    let w2 = thread::spawn(move || {
        let _ga = a2.lock().unwrap();
        let _gb = b2.lock().unwrap();
        // Critical section: w2 holds both a and b (R2)
        // ... work ...
    });

    // Main task started the group (R1) and waits for both workers (R8)
    w1.join().expect("w1 panicked");
    w2.join().expect("w2 panicked");

    // Printed only after both workers have completed (R8, R9)
    println!("DONE done=1");
}
```

## Defects repaired / hazards avoided

1. **Deadlock via inconsistent lock ordering (R5, R7).** The classic defect is one worker taking `a` then `b` while the other takes `b` then `a`, forming a wait cycle. Both workers here acquire in the identical order `a → b`, so no cycle can form and every interleaving terminates.

2. **Premature release / partial hold (R2, R3).** A common bug is releasing `a` before acquiring `b`, so the worker never holds both at once. Here `_ga` and `_gb` are both alive across the whole critical section, guaranteeing simultaneous hold. RAII guards release each mutex exactly once, at scope exit — no double-unlock, no forgotten unlock, and release still happens if the worker panics.

3. **Mutual exclusion (R4).** `Mutex::lock()` blocks until the mutex is free, so at most one worker holds `a` (or `b`) at any moment; `lock()` returning a guard (not a `try_lock` fallback) satisfies R6's "waits until it becomes free."

4. **Early exit / missing join (R8, R9).** The main task joins `w1` and `w2` before printing, so `DONE done=1` appears exactly once, after both workers complete, and the program then exits.

5. **Shared ownership across threads.** `Arc<Mutex<()>>` gives each worker safe access to the same lock instances; cloning the `Arc` clones the handle, not the mutex, so both workers genuinely contend for the same `a` and `b`.
