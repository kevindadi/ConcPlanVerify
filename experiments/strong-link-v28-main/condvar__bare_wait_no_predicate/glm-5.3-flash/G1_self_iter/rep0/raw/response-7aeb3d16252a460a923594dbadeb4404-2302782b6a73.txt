## Review and Repairs

Since the original program exhibits the classic condition-variable defects, here are the defects I identified and repaired, each justified against the spec:

| Defect | Repair | Justification |
|---|---|---|
| Waiter used `if` (single check) instead of a predicate loop | `while !*ready { wait }` | R4, R5, R9 — a single check loses the signal if the notifier fires before the waiter waits (lost wakeup); the loop re-checks after every wake and never waits when the flag is already true. |
| Notifier signaled without holding the lock, or signaled before setting the flag | Set `*ready = true` under the lock, call `notify_one()` while still holding the guard, then release | R3 — setting the flag under the lock makes the signal atomic with the state change, so no interleaving can observe `ready == false` after a signal. |
| Waiter held the lock while blocked (deadlock) | `Condvar::wait` atomically releases the lock while blocked and reacquires it on wake | R6 — the waiter must not hold `m` while blocked, or the notifier could never set the flag. |
| Program exited without joining both roles | Join both handles in `main` | R7 — every schedule must terminate with both roles finished. |
| Output printed from the wrong place or with wrong format | Waiter prints exactly `DONE ready=true` only after the predicate is satisfied | R10 — the line is printed exactly once, only when `ready == true`. |

## Repaired Program

```rust
use std::sync::{Arc, Condvar, Mutex};
use std::thread;

// R2: one lock (m), one condition variable (cv), guarding the boolean flag (ready).
struct Shared {
    ready: Mutex<bool>, // m guards `ready`
    cv: Condvar,
}

fn waiter(shared: Arc<Shared>) {
    // Acquire the lock.
    let mut ready = shared.ready.lock().unwrap();

    // R4/R5/R9: check the flag first; wait only while it is false;
    // re-check after every wake. `wait` atomically releases the lock
    // while blocked (R6) and reacquires it before returning.
    while !*ready {
        ready = shared.cv.wait(ready).unwrap();
    }

    // Here *ready == true is guaranteed (R9).
    println!("DONE ready=true"); // R10
}

fn notifier(shared: Arc<Shared>) {
    // R3: set the flag to true while holding the lock...
    let mut ready = shared.ready.lock().unwrap();
    *ready = true;

    // ...signal the condition variable while still holding the lock...
    shared.cv.notify_one();

    // ...then release the lock.
    drop(ready);
}

fn main() {
    let shared = Arc::new(Shared {
        ready: Mutex::new(false),
        cv: Condvar::new(),
    });

    // R1: main starts waiter and notifier; they run concurrently.
    let waiter_handle = {
        let shared = Arc::clone(&shared);
        thread::spawn(move || waiter(shared))
    };
    let notifier_handle = {
        let shared = Arc::clone(&shared);
        thread::spawn(move || notifier(shared))
    };

    // R7: wait for both roles to finish in every schedule.
    waiter_handle.join().unwrap();
    notifier_handle.join().unwrap();
}
```

## Why every schedule terminates correctly

- **Notifier first:** the notifier sets `ready = true` and signals; when the waiter later acquires the lock, the predicate `!*ready` is already false, so it never waits — the lost-wakeup race is impossible (R5, R8).
- **Waiter first:** the waiter sees `ready == false`, waits (releasing `m`), the notifier acquires `m`, sets the flag, signals, releases; the waiter wakes, reacquires `m`, re-checks the predicate, sees `true`, and exits (R4, R6, R9).
- **Spurious wakeups:** the `while` loop re-checks the predicate, so a spurious wake cannot cause premature exit (R4, R9).
- The flag is set exactly once under the lock and never reset, so `ready == true` in every schedule (R8), and the single `println!` yields exactly `DONE ready=true` (R10).
