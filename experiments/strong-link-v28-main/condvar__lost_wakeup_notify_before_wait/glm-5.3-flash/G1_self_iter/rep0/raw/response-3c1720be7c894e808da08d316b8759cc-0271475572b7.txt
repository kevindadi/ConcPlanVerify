```rust
use std::sync::{Arc, Condvar, Mutex};
use std::thread;

fn main() {
    // R2: one lock (m), one condition variable (cv), one boolean flag (ready) guarded by m.
    let shared = Arc::new((Mutex::new(false), Condvar::new()));

    let waiter_shared = Arc::clone(&shared);
    let notifier_shared = Arc::clone(&shared);

    // R1: main starts waiter and notifier running at the same time.
    let waiter_handle = thread::spawn(move || waiter(waiter_shared));
    let notifier_handle = thread::spawn(move || notifier(notifier_shared));

    // R8: join both roles so every schedule terminates with both finished.
    waiter_handle.join().expect("waiter thread panicked");
    notifier_handle.join().expect("notifier thread panicked");
}

fn waiter(shared: Arc<(Mutex<bool>, Condvar)>) {
    let (m, cv) = &*shared;
    // R7: acquire the lock to read the flag.
    let guard = m.lock().unwrap();
    // R4: check the flag while holding the lock; wait only while it is false;
    // re-check after every wake (the `while` loop handles spurious wakeups
    // and the missed-signal race in R5).
    let mut guard = cv.wait_while(guard, |ready| !*ready).unwrap();
    // R7: the lock is released when `guard` is dropped; the waiter was not
    // holding it while blocked (Condvar::wait_while releases it internally).
    drop(guard);

    // R9/R10: the flag is true here in every schedule.
    println!("DONE ready=true");
}

fn notifier(shared: Arc<(Mutex<bool>, Condvar)>) {
    let (m, cv) = &*shared;
    // R3: set the flag to true while holding the lock...
    let mut guard = m.lock().unwrap();
    *guard = true;
    // R6: the flag is true before the signal is issued, so a waiter that is
    // about to wait (or already waiting) can never miss the notification.
    cv.notify_one();
    // R3: ...and then releases the lock (guard dropped at end of scope).
}
```

## Defects repaired and justification

1. **Missed-signal race (R5, R6).** A naive version that signals *before* setting the flag, or sets the flag without holding the lock, loses the wakeup: the waiter evaluates the predicate, sees `false`, and blocks just after the notifier's signal fires. The fix is the canonical pattern: the notifier holds `m` while writing `ready = true` and only then calls `notify_one`. Because the waiter must hold `m` to observe `ready`, the flag write and the predicate check are serialized by the same lock, so no interleaving can slip a signal between "check" and "wait."

2. **Predicate re-check after wake (R4, R8).** Using `wait_while` (equivalent to `while !ready { cv.wait(guard) }`) instead of a single `if` re-checks the flag after every wake. This is required for correctness under spurious wakeups and guarantees the waiter only exits the loop when `ready == true`, so R9 holds in every schedule.

3. **Lock held while blocked (R7).** `Condvar::wait_while` atomically releases `m` while the waiter is blocked and reacquires it before returning, so the notifier can never deadlock trying to take the lock.

4. **Termination and output (R8, R10).** Main joins both threads, so the program exits only after both roles finish. The waiter prints exactly `DONE ready=true` once, after observing `ready == true`; nothing else is printed, and both threads' panics would surface via `join().expect(...)`, so silent partial output is impossible.

5. **Shared-state discipline (R2, R7).** `ready` is reachable only through the `Mutex` guard; there is no unsynchronized read or write of the flag anywhere in the program.
