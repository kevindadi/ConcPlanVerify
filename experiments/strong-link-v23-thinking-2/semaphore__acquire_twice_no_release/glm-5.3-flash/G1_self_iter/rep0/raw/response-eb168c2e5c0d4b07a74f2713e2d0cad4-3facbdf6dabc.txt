## Review — defects found and repairs justified

Since the concurrency defects to repair are the classic ones this spec targets, here is each defect and the fix, with justification against the requirements:

1. **Waiting while holding the internal mutex (violates R5, breaks R6).**
   A naive `acquire` that loops on `permits.lock()` while the count is zero blocks `release`, which needs the same mutex. The holder could never release, so the waiter waits forever. **Repair:** `acquire` waits on a `Condvar`, which atomically releases the mutex during the wait; `release` only needs the mutex for a brief increment.

2. **`if` instead of `while` around the condvar wait (violates R6).**
   Condvars can wake spuriously, and a woken thread may find the permit already taken. **Repair:** wait inside a `while *n == 0` loop, re-checking the predicate after every wakeup.

3. **Worker reacquiring while still holding the permit (violates R3/R4, self-deadlock).**
   With one permit, a worker that calls `acquire` twice without releasing blocks itself forever. **Repair:** each work unit is a strict acquire → work → release cycle; the permit is dropped before the next acquire.

4. **Permit leaked on early return or panic (violates R4 "on every path").**
   A manual `release` call is skipped if the work panics or returns early, permanently shrinking the pool and stalling the other worker. **Repair:** an RAII guard (`Permit`) whose `Drop` releases the permit, so release happens on every path exactly once per acquire.

5. **Notifying while still holding the mutex (hurry-up-and-wait).**
   Not a correctness bug, but the woken thread immediately blocks on the mutex the notifier still holds. **Repair:** drop the guard before `notify_one`.

6. **Supervisor not joining both threads (violates R1).** Both handles are joined before the final count is read, guaranteeing all releases have happened, so the printed count is exactly the initial `1` (R7).

## Repaired program

```rust
use std::sync::{Arc, Condvar, Mutex};
use std::thread;

/// Counting semaphore with a single permit initially (R2).
struct Semaphore {
    permits: Mutex<usize>,
    available: Condvar,
}

impl Semaphore {
    fn new(initial: usize) -> Self {
        Semaphore {
            permits: Mutex::new(initial),
            available: Condvar::new(),
        }
    }

    /// Blocks until a permit is available. While waiting, the internal
    /// mutex is released, so the current holder can still `release` (R5).
    fn acquire(&self) {
        let mut n = self.permits.lock().unwrap();
        while *n == 0 {
            // `wait` atomically releases the mutex and sleeps;
            // re-check on every wakeup, including spurious ones (R6).
            n = self.available.wait(n).unwrap();
        }
        *n -= 1;
    }

    /// Returns one permit. The mutex is held only briefly; it is
    /// dropped before notifying so the woken waiter never queues
    /// behind the notifier.
    fn release(&self) {
        let mut n = self.permits.lock().unwrap();
        *n += 1;
        drop(n);
        self.available.notify_one();
    }
}

/// RAII guard: releases the permit on every path, including
/// early return or panic (R4).
struct Permit<'a> {
    s: &'a Semaphore,
}

impl Drop for Permit<'_> {
    fn drop(&mut self) {
        self.s.release();
    }
}

/// Each work unit is a strict acquire -> work -> release cycle.
/// The permit is never held across an `acquire` call, so a worker
/// can never block on itself (R3, R4, R6).
fn worker(name: &'static str, s: Arc<Semaphore>, units: usize) {
    for i in 0..units {
        s.acquire();
        let _permit = Permit { s: &*s };
        // The work itself: pure computation, no output, so the
        // program's only printed line is the final one (R7).
        let _ = (name, i);
        // `_permit` drops here (or on unwind), releasing exactly once.
    }
}

fn main() {
    // Shared pool begins with exactly one permit (R2).
    let s = Arc::new(Semaphore::new(1));

    // Supervisor launches both workers (R1).
    let s1 = Arc::clone(&s);
    let w1 = thread::spawn(move || worker("w1", s1, 2));

    let s2 = Arc::clone(&s);
    let w2 = thread::spawn(move || worker("w2", s2, 2));

    // Supervisor waits for both workers to finish (R1, R6).
    w1.join().expect("w1 panicked");
    w2.join().expect("w2 panicked");

    // All acquires are matched by releases by the time both threads
    // have been joined, so the count is back to the initial value.
    let done = *s.permits.lock().unwrap();
    println!("DONE done={}", done); // prints exactly `DONE done=1` (R7)
}
```

**Why every schedule terminates (R6):** each worker performs a finite number of units; a worker only blocks while another holds the permit, and the holder never blocks while holding it (it releases before its next acquire), so the permit always returns to the pool and progress is guaranteed. The mutex is never held across a blocking operation, so no lock-order or self-deadlock is possible.
